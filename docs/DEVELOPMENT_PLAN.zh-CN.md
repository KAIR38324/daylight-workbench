# 教室采光代理模型多目标优化工作台：P0 开发与验收计划

日期：2026-10-20。此文件是计划，不是已完成功能声明；实际交付状态见 README 和验收记录。

## 1. 目标与边界

把“数据表 → 多输出 ANN → NSGA-II → 候选方案筛选 → 导出复核”收敛到一个桌面程序。使用者是需要研究代理模型优化、而不希望在 Grasshopper、Python 和多个插件间反复搬运模型与结果的研究者。Windows x64 桌面交付优先，离线完成核心流程，无账户、云同步、后台服务或数据库。

外部流程保留：DSE / Ladybug Tools 调用 Radiance / EnergyPlus 生成数据；本平台不替代物理仿真，不承诺几何、规范或实际采光达标。ANN 优化结果统一称为“代理模型预测的非支配候选方案”，需重新仿真才能验证。

P0 不做：自动仿真调度、Grasshopper 双向桥接、AutoML、大规模超参搜索、多用户协作、云计算训练、主动学习、复杂三维建模。

## 2. 技术与架构

- Python、PySide6、matplotlib：桌面界面与图表。
- pandas / openpyxl：CSV / XLSX 导入。
- scikit-learn / NumPy：拆分、缩放与指标。
- CPU PyTorch：多输出 MLP。CPU 默认避免 CUDA 安装负担。
- pymoo：NSGA-II，不自行重写排序与拥挤距离算法。
- 科学核心不依赖 Qt，便于独立测试；耗时训练和优化放入后台任务，单任务运行，支持取消。
- JSON、CSV 和受限模型权重保存版本化项目，不加载任意 Python pickle 对象。

以功能轻量为目标，而非承诺包体极小：PyTorch 和 Qt 的运行时仍可能使分发包较大。首发优先文件夹式 EXE，减少单文件自解压与排错复杂度。

## 3. 数据配置

每列可指定为输入、目标或忽略；可选 ID / 分组列。通常 9–12 个输入、2–4 个目标，但不把典型数量写死。目标方向必须由用户确认，不从名称猜测。

默认 70% / 15% / 15% 训练、验证、测试，随机种子 42，可调整。相同输入设计不得跨集合；同教室、同基础几何或同场景族的相关样本应使用分组划分。分组后的实际行数比例可能不完全等于设定比例，界面应显示实际数量。保存具体拆分成员而非仅保存随机种子。

检查非数值、缺失、无穷值、重复输入、冲突目标、常量列。不得默默填值或删行。P0 首先支持数值连续、整数与固定变量；无法正确处理的类别变量明确拒绝，不用随意编码伪装支持。

## 4. ANN 训练与验证

初始设置：隐藏层 64/64、ReLU、线性多输出层、Adam、学习率 0.001、固定种子、验证集早停并恢复最佳权重。训练预算可配置，不启动自动超参穷举。

先拆分，后仅在训练集拟合 X 与 Y 的缩放器。验证集用于早停；测试集仅用于冻结模型的报告，不能反过来挑选模型而仍把它称为独立测试。

按每个目标的原始单位报告 MAE、RMSE、R²；常量测试目标的 R² 应标为未定义，不能显示误导性满分。显示训练/验证损失和实测—预测图。有条件时加入训练均值基线。小样本或分组过少需要风险提示，不能把任意固定样本数当作充分性的保证。

## 5. NSGA-II

轻量首发默认种群 80、代数 60，用户可调；单次评估上限 20,000，避免候选归档排序耗尽内存。最大化目标在优化 API 内转符号，展示与导出保持原单位、原方向。模型在评估候选前落实整数/固定值，不能仅在最后导出时取整。

变量范围默认在训练样本支持范围内；超出范围默认阻止。轴向上下界不代表组合处于训练分布内，也不代表建筑几何可行，界面与导出均须说明。耦合几何约束和物理约束需要真实案例定义，不凭空宣称已经覆盖。

按优化预算与随机种子保存运行信息，记录模型标识和数据指纹。无可行解、取消和异常必须与成功分开。

## 6. 可视化与分析

- 可选择目标轴的二维帕累托散点图。
- 多目标平行坐标，明确是否归一化，表格保留原始量纲。
- 稳定候选 ID、可排序结果表、输入/目标范围筛选、选中方案导出。
- 导出所有候选或选中候选的输入值、预测目标与来源信息，供 LBT 再仿真。
- LLM 是后续可选功能，不阻塞 P0 手动分析。只把自然语言转成可审阅的结构化筛选/排序计划，再由程序确定性执行；不能生成新预测或虚构候选。任何联网前明确提供方、发送字段和用户授权，API 密钥不进项目/日志。

## 7. 持久化与错误处理

保存配置、列顺序、数据指纹、拆分索引、训练配置、权重、缩放参数、评估结果及优化记录。重新打开后预测应一致。更换数据或改变影响模型的配置后，不得静默复用旧结果。取消/失败保留上一个有效结果，不把半成品标记完成。避免 GUI 阻塞、重复提交和窗口关闭时仍写入已销毁状态。

## 8. 交付阶段

A：架构审查与数据契约。退出条件是明确范围、默认值、未知领域规则和测试门槛。

B：离线纵向闭环。合成数据导入 → 训练 → 评估 → 优化 → 筛选 → 导出 → 保存/重开。合成数据只能验证软件流程，不能证明真实采光研究效果。

C：独立验证与修复。较低成本模型执行测试、核对数值与失败路径；发现算法/数据泄漏等问题再交实现模型处理。只对变更跑相关测试，发布前再做完整回归。

D：Windows 构建与验收。使用 Windows 原生构建环境产出 EXE，在无项目开发环境依赖的条件下验证核心流程。Linux 测试不替代 Windows 验收。若 Windows 资源或上传权限待确认，则明确保持该门槛未完成。

E：真实数据验收。用户提供脱敏数据、变量/目标含义、分组规则、边界及可接受误差。检查代理模型是否足以支持当前研究。该门槛不能由软件单元测试代替。

## 9. 必须验证的项目

1. CSV/XLSX 列映射、非法数据、重复输入与分组。
2. 三个集合行/组互斥；测试集异常值不能影响训练缩放参数。
3. 原单位指标独立复算一致，常量目标指标无误导。
4. 模型保存重载预测一致，错误版本与不匹配字段被拒绝。
5. 已知解析目标验证目标方向、非支配关系和整数变量约束。
6. 同种子在锁定环境内重现结果；不承诺跨平台位级一致。
7. 取消、失败、重复点击、重配置不产生过期结果。
8. 断网完成核心端到端流程，导出可被重新读取。
9. Windows 打包产物启动与核心流程通过，中文路径得到验证。
10. 真实数据模型质量与 LBT 复核另行记录。
